# Phase 5 — Training-Corpus Plan & Decision Points (PLAN §5)

Status: **DESIGN COMPLETE — generation blocked on the Z.ai API key** (escalated to owner
2026-08-14). This document is the decision basis: what is ready, what each path costs,
what approval unblocks. Repo-scale data plumbing is required identically on both paths.

## Requirements carried from PLAN §5 / GOAL.md

- Mixture: ~35% whole code repositories · 30% synthetic long-context reasoning ·
  15% long natural documents · 10% coding-agent trajectories · 10% short replay.
- **Every task machine-checkable** (planted needles, compiled tests, deterministic keys);
  teacher-verification pass; flawed generations filtered, not hand-repaired.
- **Strict exclusion** of all evaluation repositories/benchmarks from training data —
  enforced by `data/exclusions/eval_repos.json` (108 repos: SWE-bench Verified +
  LongCodeBench/LCB; rebuilt by `scripts/build_exclusion_list.py`; RepoQA to append when
  its repo list is located — suite currently unintegrated).
- Length buckets: 32–64k / 64–128k / 128–256k / 256–512k targets; genuine sequences
  dominate per PLAN §7 mixture (55–70% genuine 96–256k).

## Path A — GLM-5.2 teacher via Z.ai API (preferred; blocked)

- Ready: design (batched templates, full prompt/completion caching, seeds + params logged,
  regenerate-or-discard verification pass). Generator would emit directly into
  `TrainingSample`-shaped records via `src/muse_longctx/position_sampler.py`.
- Blocked: no `ZAI_API_KEY` in `.devcontainer/.env`. Nothing to build against until provided.
- Unblocked by: owner adds key (same mechanism as `HF_TOKEN`, generated by
  `detect-host-gpu.sh` or manual append — never committed).

## Path B — interim self-generated corpus (no teacher; viable now)

Stack-v2 access verified with the current HF token (gated=auto). Composition:

1. **Repo scale (35%)**: Stack-v2 permissive-license repos (MIT/Apache/BSD), size-bucketed,
   exclusion-filtered, assembled into repo-rendering documents (path-commented file tree,
   deterministic order) at 32k–512k.
2. **Synthetic long-context reasoning (30%)**: same generator family as the eval suite but
   with disjoint surface templates + randomized namespaces (codebase: planted-symbol
   questions, cross-file API tracing, config-resolution chains; prose: entity-state
   tracking, conflict resolution, aggregation) — answers are planted ground truth by
   construction, so verification = programmatic (no teacher needed for correctness, only
   for answer style).
3. **Natural long documents (15%)**: public-domain books/manuals (NoLiMa's bundled books
   are Adobe-licensed — excluded; use Project Gutenberg / technical doc corpora), with
   cross-section synthesis questions whose keys are extracted deterministically (e.g.
   stated facts with unique surface forms, verified single-occurrence).
4. **Agent trajectories (10%)**: deferred to Path A (a capable agent teacher matters here;
   self-generated trajectories risk style collapse). If Path A stays blocked, replace with
   replayed tool-call transcripts assembled from Stack-v2 issue/PR discussions.
5. **Short replay (10%)**: instruction/coding data from open SFT sets, license-checked,
   eval-decontaminated.

Cost estimate (Spark, CPU-side): repo assembly + generation templating are I/O-bound;
1–2 days for a first ~200–500 M-token corpus slice, dominated by Stack-v2 selective
download (a few languages, streaming, license + exclusion filters).

2. If Path B: confirm Stack-v2 download volume budget (~200–500 GB selective) is

## Enforcement (both paths)

- Corpus build scripts read `data/exclusions/eval_repos.json` and assert zero overlap at
  assembly time (fail-closed), plus n-gram decontamination against suite prompts (NoLiMa
  needles excluded by license; LQA/LBv2/∞Bench answer strings never enter training data).
- Every generated sample records: source repo/doc ids, license, template id, seed,
  ground-truth key, verification result.
